# New Capability Evaluation
## Emerging Capabilities Lane — AI Discovery Journey

**Status:** Internal Working Draft v0.1
**Purpose:** A repeatable one-pager for triaging any new AI feature before we recommend it to clients. New capabilities arrive constantly; this is how we keep the journey framework current instead of stale — and how we turn "keeping up with AI" into a deliverable service rather than a scramble.
**Owner:** The fractional AI expert. Run one whenever something notable ships (new Copilot feature, Claude capability, an autonomous/"Co-work"-class tool, a third-party integration).

---

## Evaluation

**Capability:** _______________________  **Vendor/tool:** _______________  **Date:** __________  **Evaluated by:** __________

### 1. What is it?
_Plain-language description. What does it actually do that we couldn't do before?_

### 2. Who would care?
_Which clients / roles / spine stages does this matter for? Attended or unattended?_

### 3. Sandbox test
_What we tried, on dummy/non-sensitive data. What worked, what didn't, what surprised us._
- Result: 🟢 impressive / 🟡 promising-but-rough / 🔴 not ready

### 4. Risk & governance
- Does it touch real data? What data?
- Attended or **unattended**? If unattended → heavier gate applies.
- Licensing / cost implications?
- What could go wrong, and what's the blast radius?
- What guardrails would a client need before using it for real?

### 5. Verdict
- [ ] **Adopt** — fold into the experiment deck / training now
- [ ] **Park** — promising but not ready; revisit on ____________
- [ ] **Reject** — not useful or not governable for our clients

### 6. If adopting
- New experiment card to write: _______________
- Which stage / track it belongs to: _______________
- Governance notes to carry into the gate: _______________
- Worth featuring in monthly sessions as the "one new thing"? Y / N

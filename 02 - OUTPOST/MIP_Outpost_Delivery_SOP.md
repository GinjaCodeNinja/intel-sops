## 1. Purpose & who this is for
- The playbook for an AI Expert running the **ongoing** Outpost engagement (post-onboarding).
- **Assumes onboarding is complete** — see `NCA_Outpost_Onboarding_SOP.md`: client is on Outpost, working group stood up, tracking open, first focus picked, cadence booked.
- Pairs with: the Onboarding SOP, the 4-beat session format (`NCA_Fractional_Expert_Session_Format.md`), the journey framework, the readiness tracker, and the experiment cards.

## 2. Precondition — client is onboarded
- Intake, commercial sign-off, provisioning, standing up the working group, and setting cadence all happen in **`NCA_Outpost_Onboarding_SOP.md`**.
- Before Session 1, confirm the **Ready-for-Delivery checklist** (Onboarding SOP §9) is complete: working group stood up · tracker + log open · first focus picked · cadence booked · governance minimum or catch-up backlog in place.

## 3. Kickoff → handled in Onboarding
- The kickoff (journey overview, expectations, confirming the working group, picking the first focus, setting cadence) is the **last step of onboarding** — see `NCA_Outpost_Onboarding_SOP.md` §7. Delivery begins at **Session 1 (§4)**.

## 4. Where we start — Session 1 ⟨PENDING default → Register §C3⟩
- Default opening play (draft):
  - Set a **Copilot fluency baseline** — what are they actually using today?
  - Frame with the two framing questions (what should AI access · where's the source of truth) — the same ones used in the Pathfinder kickoff.
  - Stand up the **pull-menu** — hand the working group the experiment cards.
  - Pick 1–2 starter experiments to run before next session.
- If they're further along: jump to a **Workflow Deconstruction** on a real workflow.

## 5. The monthly rhythm *(the core loop)*
- Run the **4-beat session** every time — see `NCA_Fractional_Expert_Session_Format.md`:
  1. What landed (review the log; capture the leadership win)
  2. Unblock
  3. What's next (suggest cards; coach the concept)
  4. One new thing (Emerging Capabilities)
- Apply **per-stage emphasis** (fluency → workflow thinking → first builds → productionize).
- Close each session: agree what the group tries next; flag anything waiting on a gate.

## 6. Default first-90-days arc *(starting template — easy to deviate)* ⟨PENDING how prescriptive → Register §C4⟩
- **Session 1:** fluency baseline + stand up working group + first experiments (see §4).
- **Session 2:** review what landed; run a **Workflow Deconstruction**; introduce the AI/automation/human triage.
- **Session 3:** first **guided build** (a simple declarative agent or automation) on governed data; measure it.
- Thereafter: iterate — productionize what lands, keep the foundation catching up.

## 7. Cadence variations
- **Monthly** = default (1 included hour).
- **Accelerated / bi-weekly** = the AI Consulting Pricing Model already prices this automatically via its frequency term — no separate add-on package to negotiate. ⟨PENDING confirm → Register §D3⟩
- **Extra hours** = requested → confirmed → booked + billed at the model's $200/hr consulting rate. ⟨PENDING flow → Register §D4⟩
- **Quiet client** = defined nudge sequence, then flag to AM. ⟨PENDING → Register §D5⟩

## 8. Build & agent work
- **Included vs. billable:** light advise/design/config in the hour; larger builds = billable sprint. ⟨PENDING line → Register §E1⟩
- **Who builds:** AI Expert (light) or hand to PS/dev. ⟨PENDING → Register §E2⟩
- **Gate routing:** build needs ungoverned data → sandbox on dummy data + fast-track that workspace through Rail B; never build on un-signed-off real data. *(framework §9)*
- **Unattended / Claude / third-party = Frontier**, not Outpost — flag as a graduation signal, don't deliver it under Outpost.

## 9. Tracking & reporting
- Keep the **experiment log** current (who keeps it ⟨PENDING → Register §F1⟩) — it feeds the session and the ROI story.
- Update the **readiness tracker** (Rail B progress + any catch-up backlog items).
- Give the client a **monthly one-page** what-landed / ROI summary. ⟨PENDING format → Register §F2⟩
- Record session notes in the client record (IT Glue / SharePoint list / spreadsheet for now), outcome language.

## 10. Boundaries (consult-construct do / don't)
- **Do:** advise, design, coach, de-risk, unblock, suggest, sandbox.
- **Don't:** make business decisions, own operations, approve AI outputs for them, or guarantee productivity/accuracy/compliance outcomes. ⟨confirm wording → Register §E3⟩

## 11. Roles & handoffs
- **AM ↔ AI Expert:** warm-lead handoff in; relationship/renewal issues out. ⟨PENDING intake → Register §A2, §G4⟩
- **AI Expert ↔ PS/dev:** larger builds. ⟨PENDING → Register §E2⟩
- **Client assignment:** a single AI Expert owns each client. ⟨PENDING → Register §G2⟩
- **Coverage:** named backup with access to the client record. ⟨PENDING → Register §G3⟩
- **Escalation:** unhappy client / failed build → path. ⟨PENDING → Register §G4⟩

## 12. Exit / graduation to Frontier
- Watch for signals: mature Copilot use, wants Claude / third-party / integrations, first agents live and valued.
- Raise the Outpost→Frontier conversation (who raises it ⟨PENDING → Register §F3⟩); run the graduation gate for anything moving to production. *(framework §5 Prove & Productionize)*
